# Gotchas

> Part of the MonkeyX Core docs. See [`../CLAUDE.md`](../CLAUDE.md) for the index.

## Gotchas

- **target can be None**: `monkeyx.py` only sets `module_kwargs['target']` if `args.target` is truthy. Modules that require target will get a KeyError if validation is bypassed.
- **url_file/target are ledger-driven**: When running through the orchestrator with `output_dir`, `target`, `url_file`, and `domainlist` kwargs are regenerated from the ledger before each step. Module defaults only matter if a module is called directly outside the orchestrator.
- **Plugin load order**: Built-in modules load first, then env var plugins, then ~/.monkeyx/, then entry points. Later wins on name conflicts.
- **dns_resolve / dnsx_resolve read from the ledger**: Both modules resolve hostnames from the target file (IPs/hostnames) and the domainlist kwarg. Results (hostname→IP mappings) are logged to the ledger so subsequent modules pick up resolved IPs via regeneration. Both have internal scope filtering against the target file's CIDRs. `dnsx_resolve` wraps projectdiscovery's dnsx (returns full DNS records via `-recon`, plus a PTR pass — see below); `dns_resolve` is the pure-Python alternative.
- **dnsx_resolve (dnsx wrapper)**: Runs projectdiscovery's `dnsx` locally. `dnsx_resolve` (REQUIRED_INPUTS=empty — can run with targets, domains, or both) resolves hostnames from the target file, domainlist kwarg, and any subfinder/puredns bruteforce output found in the data dir; forward resolve flags = `-recon -j -or`. Produces JSONL output including A, AAAA, CNAME, NS, MX, TXT, SRV, PTR, SOA, CAA, ASN, and wildcard fields. In domain-only workflows (no `-t`), it resolves discovered subdomains to IPs which land in the ledger as **name-safe** (`dl`) targets — scanned by web/URL modules (httpx/nuclei/gowitness/…), but NOT port-scanned: nmap/ssh/smtp/snmp are host-full modules and only run on `-t` (`t`-channel) targets, so a domain-only run performs no port scan (pass `-t <ips/cidrs>` to port-scan resolved IPs). **PTR (reverse DNS)**: after forward resolution, runs a second pass with `-ptr -j -or` on ALL IPs (passthrough from target file + newly resolved). PTR hostnames are logged to the ledger as subdomains (parented at the IP), and the IP is re-logged with the PTR hostname as parent — this populates `get_ip_to_hostnames()` so URL synthesis emits hostname URLs alongside IP URLs for gowitness/nuclei/ffuf/feroxbuster. Example: IP `10.1.1.1` with PTR `portal.example.com` and port 8080 open → gowitness screenshots both `http://10.1.1.1:8080` and `http://portal.example.com:8080`. PTR scan failure is non-fatal (forward resolve results still succeed). **Important**: we deliberately do NOT pass `-silent` (need stderr to surface dnsx errors when they happen). `dnsx_resolve` also writes a copy of its actual hostname input to `data/step-snapshots/` for forensics.
- **ax_puredns_bruteforce (fleet-distributed subdomain bruteforce)**: Uses the built-in `puredns-bruteforce` ax module to bruteforce subdomains. REQUIRED_INPUTS={"domainlist"}. Wordlist and resolvers are configured on the fleet nodes — no extra flags needed. Command: `ax scan '{domainlist}' --fleet '{fleet}' -m puredns-bruteforce -w '{wordlist}' -o '{output}'`. Produces plaintext output (one subdomain per line). The `_log_subdomains_from_file` helper in `workflows.py` seeds the ledger with discovered subdomains. **Important: bruteforce only runs against user-provided root domains (`-d`), NOT against discovered subdomains.** The orchestrator calls `ledger.export_root_domains()` before bruteforce modules, which exports only the original explicit domains — this prevents recursive looping where discovered subdomains would be fed back as bruteforce input.
- **scope_filter default is strict**: The `--scope-filter` flag defaults to `strict`. Out-of-scope discoveries are logged to the ledger but not exported to module target files. Use `--scope-filter warn` or `--scope-filter none` to include them.
- **Exclusion list (`--exclude FILE`)**: Pass a file listing targets to exclude (one per line). Supported formats: bare IP, CIDR, plain hostname (matches the host AND any subdomain — e.g. `legacy.example.com` excludes `api.legacy.example.com`), `*.domain` (subdomains only, NOT the bare domain), full URL (exact match). Exclusions ALWAYS win — they override `-t`/`-d`/`-url` (with a warning log) and short-circuit parent-chain inheritance, regardless of `--scope-filter` mode. Excluded targets are still logged to `discovery-ledger.jsonl` with `scope: "excluded"` for audit, but never written to `ledger-{targets,urls,domains}.txt`. Implementation: `core/target_ledger.py:seed_exclusions()` and `is_excluded()`. **Persistence across continue/resume:** the raw `--exclude` rule lines are saved to the `exclusions` table in `scan.db`, and `--continue`/`--resume` re-seed them (`seed_persisted_exclusions()`) **before** `load_from_disk()` runs the scope fixpoint — so exclusions are honored even when `--exclude` isn't re-passed, and a previously-excluded target can't silently re-enter scope. A newly-passed `--exclude` on continue/resume is merged with the persisted rules.
- **Background modules**: The engine supports running modules listed in `_BACKGROUND_MODULES` (`workflows.py`) in a separate thread so they don't block the pipeline, waiting for them at the very end. The set is currently **empty** — no module runs in the background today. If you add one, only use it for modules whose output is self-contained (nothing downstream consumes their targets/URLs).
- **Early fleet kill**: After the last fleet-requiring step completes, the fleet is killed immediately even if local/background modules are still running. The `finally` block checks `fleet_killed_early` to avoid double-kill.
- **nmap merge sanitizes per-host XML first**: `merge_nmap_folder` (`core/scanning.py`) delegates the actual merge to axiom's `nMap_Merger.py`, which parses each per-host `*.xml`. `nmap -sV` can emit binary service banners (e.g. Samba on 445) that land in the XML as raw control bytes or numeric refs to illegal codepoints (`&#x2;`) — making that file non-well-formed, so a strict parser throws and the merger **silently drops the whole host** from the merged output (its ports never reach the ledger; every downstream module then misses it while nmap still reports success). So we strip illegal XML chars/refs from each per-host file **before** the merge (recovering the host), and afterward cross-check the merged host set against the per-host files — any remaining loss downgrades `ax_nmap_tcp`/`ax_nmap_udp` to a **warning** listing the dropped IPs instead of a clean success.
- **nmap coverage reconciliation (`uncovered_ip_targets`)**: broader than the merge check above — `ax` scans always exit 0 and never report per-host collection failures, so a fed target that was never scanned/collected (dead fleet instance, failed result pull, *or* a merge drop) would silently vanish from results. After the merge, `ax_nmap_tcp`/`ax_nmap_udp` diff the fed bare-IP targets (`ledger-targets.host.txt`) against the hosts present in the merged XML; any fed IP with no host entry is then re-checked against its own per-host result file and only reported as `uncovered_targets` (→ `status: 'warning'`) if that file shows no completed scan. This per-host re-check is essential because the scans run with `--open`: nmap OMITS the `<host>` element for a scanned host that has zero open ports, so a quiet-but-fully-scanned host is absent from the merged XML and would otherwise be a false "uncovered" (on a mostly-quiet external range that false positive also *triggered* the warning-status discovery drop — see `_extract_discoveries`). The per-host file still records a successful `<runstats>` (`exit="success"`, `hosts up`), so `uncovered_ip_targets(scan_folder=...)` reconciles against that: present+completed = scanned (covered); missing/unparseable/incomplete = a genuine gap (dead node, failed pull, truncation). Only literal IPs are reconciled (hostnames/CIDRs are skipped — can't be matched without resolution/expansion). The warning propagates to the run status (`completed_with_warnings`, see the API layer) and the `summary`/`report.html` debrief (the consolidated **Needs Attention** block — Warnings / Coverage Gaps) so partial coverage never reads as clean.
- **Degraded-scan detection (`port_scan_health`/`port_scan_degraded`, `core/scanning.py`)**: catches the WORSE, silent failure the coverage check above misses — hosts that ARE present ("up") but the port-scan phase collected ~nothing (broken/blocked fleet nmap, missing raw-socket privilege, lost results). Real regression: 1039 hosts up, **2** open ports total, while httpx independently found 356 live on 443. The uncovered check saw the hosts as "up" (covered) and flagged only 1. Now `ax_nmap_tcp` computes `hosts_up` vs `hosts_with_open_ports` from the merged XML; when many hosts are up but <2% have any open port it downgrades to **warning** with a loud "PORT SCAN LIKELY INCOMPLETE" message and stamps `scan.db` meta `port_scan_degraded=1`. `analyze` reads that flag AND independently cross-checks (live web-endpoint hosts vs open-port hosts — a closed network can't have many live web hosts and ~zero open ports), rendering an unmissable banner at the top of `analysis.md` so near-zero port/service counts never read as a clean, closed surface. Conservative thresholds (`min_hosts=10`) so a tiny genuinely-quiet scope doesn't false-alarm.
- **bbot require-flags (`-rf`) are AND-matched — enable modules via a PRESET (`-p`), not require-flags**: bbot's `--require-flags` keeps a module only if it has EVERY listed flag (`preset.py` `not all(f in module_flags …)`). So `-rf active loud` is a trap: on bbot < 3.0 `loud` isn't a flag at all → the filter drops EVERY module and the scan silently does nothing (bbot warns "Could not find flag loud", but we run `--silent` so it's hidden and the module still returns `status: success` with 0 findings); even on bbot 3.0 it drops any module lacking `loud` (e.g. `generic_ssrf`) and the passive extraction chain (`excavate` is `passive`), starving a fuzzer of parameters. Real case: `bbot_dast` did nothing for exactly this reason. Fix pattern (mirrors `bbot_recon`): select modules with a **preset** `-p <name>` (which pulls in the right dependency chain) + explicit `-m <extra>`, and leave `require_flags=False`. `run_bbot_flags(..., require_flags=False)` emits `-p`; `require_flags=True` emits `-rf` (reserve it for genuine flag *filters* like `bbot_passive`'s `passive safe`, where the modules actually carry those flags).
- **Filtered/rate-limited hosts cause non-deterministic results (service-vs-portscan reconcile)**: a host that silently drops/rate-limits SYN scans makes nmap report **0 open TCP ports** on it, while nuclei's gentler full-connect network templates (fed the bare host, e.g. `example.com:6379`) reach the services — but only *sometimes*. Observed: two `standard` runs against the SAME `-t` host hours apart returned 90 vs 35 findings; the entire delta was nuclei network-template hits (redis/ftp/smb/smtp/ssh) on `198.18.1.9`, which nmap saw as having no TCP ports in **both** runs. Scope/commands/inputs were byte-identical — the target's reachability under scan load is what varied, so this is a target/network artifact, NOT a MonkeyX bug. To stop it reading as a clean surface, `analyze._services_outside_portscan` reconciles nuclei-discovered `host:port` services (hostnames mapped to IPs via `scan_db.host_ip_maps_from_parents`) against the ports table; any **host-full (`-t`, channel `t`)** IP with a service on a port absent from the scan sets `metadata.port_scan_incomplete_note` → a "Port-scan coverage gap" banner in `analysis.md` and a warning in the debrief's Needs Attention. Only fires when a scanner actually reached a port with an **explicit** `:port` (never infers default web ports), and only for host-full targets (name-only scope is intentionally un-port-scanned — see the name-only scope note). It also **reconciles forward** (`analyze._record_scanner_ports`): any nuclei/httpx-reached `host:port` on an in-scope IP that the port scan never logged is upserted into the `ports` table tagged `source='nuclei'|'httpx'` (last-write-wins never clobbers nmap detail), so the ports inventory / API / report are complete even where nmap under-covered. Fix for the underlying host: enable the opt-in connect-scan fallback (`modules.ax_nmap_tcp.connect_fallback`, `-sT`) which recovers the ports at scan time so the nmap-gated service modules (ssh_audit/smtp) also benefit.
- **normalize module**: Converts all tool outputs to per-tool JSONL files (nmap, nuclei, subfinder, ffuf, feroxbuster, bbot). Should always run last in a workflow.
- **output_dir is popped from kwargs**: `run_modules()` pops `output_dir`, `keep_fleet`, and `scope_filter` before passing kwargs to modules, so modules never see them.
- **Continue mode (`--continue`)**: Runs new modules/workflows against an existing output directory's target ledger. Unlike `--resume` (which replays from a checkpoint), `--continue` loads the existing ledger, optionally seeds new user inputs (additive, deduplicated), and runs the specified modules/workflows from scratch. The ledger's accumulated discoveries from prior runs are available to the new modules via normal target file regeneration. If the continue run is paused, it can be resumed normally with `--resume`. Input files (`-t`, `-d`, `-url`) are optional — if omitted, modules run against whatever the ledger already contains. **Important:** to get cross-run output versioning/merging (see below), pass the same `-o` prefix as the original run; otherwise each `--continue` invocation writes to a new prefix and behaves like a separate scan.
- **Cross-run output versioning + merge**: When a scan module runs again via `--continue` against the same output prefix, the previous canonical output (e.g., `{prefix}-nuclei.jsonl`) is moved to `data/runs/{prefix}-nuclei.run1.jsonl`. The new run's output is archived as `.run2`, and a merged + deduplicated canonical file is produced at the original path. Downstream modules (normalize, analyze, jsonl_to_csv) glob for the canonical name and consume the merged view transparently — they don't see files inside `runs/`. Versioning applies only to scan modules registered in `core/merge_outputs.py:_MODULE_MERGE_CONFIG` — the nmap/nuclei/ffuf/feroxbuster/naabu/subfinder/dns_resolve wrappers, all `bbot_*`, the recon text-tools (katana/gau/amass/testssl/corsy/dalfox/mantra/subjs/arjun), and the enrichment/protocol modules (shodan_enrich, ssh_audit_scan, snmp_sweep, smtp_security). See `_MODULE_MERGE_CONFIG` for the authoritative list + per-module dedup keys. Post-processing modules always regenerate. Dedup keys are format-specific: nmap XML by (addr, portid, protocol); JSONL by tool-specific composite (e.g., template-id+matched-at for nuclei); text by URL or full line. First runs (no `--continue`) are unchanged — no `runs/` dir is created.
- **Results archive rebuilt on every run type**: `{prefix}-results.zip` is (re)built by `_create_results_archive()` in `monkeyx.py`, called from the `finally` block of ALL THREE run paths — main, `--resume`, AND `--continue` — so a resumed/continued run overwrites the old zip with the now-fuller results (matching the API's continue endpoint). It uses each path's own prefix (main=`args.output`, resume=checkpoint `prefix`, continue=detected `output_prefix`). Best-effort: a zip failure logs and never fails the run. Contents: output-dir top-level files, `data/` top-level only (no `data/runs/`), full `reports/`+`logs/` trees, prior-run snapshots (`*.run1.*`, `report.run2.html`) skipped, plus the bundled standalone viewer. The `scan.db-wal`/`scan.db-shm` sidecars are explicitly excluded (a checkpointed `scan.db` is self-contained; bundling a live sidecar would make a read-only unzip fail to open the WAL db). Pre-run validation failures (`sys.exit(1)` before `run_modules`) produce no output and correctly build no zip.
- **Pause/resume**: Two modes controlled by `--finish-step` flag:
  - **Default (mid-step cancel)**: Ctrl+C sends KeyboardInterrupt into the running module. `workflows.py` catches it, writes `checkpoint.json` pointing at the interrupted step, exits code 42. On resume, the interrupted step is re-run from the beginning.
  - **`--finish-step` (graceful)**: Ctrl+C creates `pause.requested` sentinel. Engine finishes current step, writes `checkpoint.json` pointing at the next step, exits code 42. On resume, execution continues from the next step.
  - On resume, `ledger.load_from_disk()` rebuilds in-memory state from existing JSONL.
  - Parallel groups are atomic — checkpoint points at the group start index so the entire group re-runs on resume. On Ctrl+C mid-group, `_run_parallel_group` overrides EVERY member to `step_failed` before re-raising: worker threads keep running to completion when only the main thread is interrupted, so a member whose tool exited 0 on the signal could otherwise record `step_completed(success)` — an interrupted step must never report success.
  - Fleet is killed on all exit paths by default (completion, failure, pause). `--keep-fleet` skips cleanup entirely — fleet stays alive for reuse. Resume reinitializes if needed.
- **Fleet auto-detection**: Before calling `initialize_fleet()`, the engine runs `ax ls | grep -i <fleet>`. If matching instances exist, initialization is skipped and the existing fleet is reused with a WARNING-level log message. This means `--keep-fleet` + a new scan on the same fleet name "just works" without `--resume`.
- **Ctrl+C during fleet init**: Fleet spin-up takes 5+ minutes per instance, and instances can finish provisioning in the cloud minutes after `ax fleet` is interrupted. If Ctrl+C fires during `initialize_fleet()`, a `fleet_init_interrupted` flag is set and the cleanup path uses `kill_fleet_with_retries()` instead of a single `kill_fleet()` call. The helper runs in two phases: **Phase A (settle)** waits for the fleet to finish provisioning before issuing the kill — if `expected_nodes` is known (passed from `args.nodes`), it waits until that many appear in `ax ls`; otherwise it waits for the visible count to plateau (no growth across 3 polls × 30s = 90s). Capped at 8 minutes. **Phase B (drain)** issues `ax rm`, then polls every 30s, re-issuing kill any time stragglers appear. Exits early once the fleet has stayed empty across a streak of consecutive polls (2 if expected count was known, 6 otherwise). Total cap 15 minutes. A second Ctrl+C during polling aborts the wait and prints the manual `ax rm "<fleet>*" -f` command.
- **ax SSH ControlPath can overflow the Unix-socket path limit**: ax (`axiom-scan`) puts SSH ControlMaster sockets at `$AXIOM_PATH/tmp/$uid/sockets/<node-ip>`, where `uid="$module+$(date …)"`. The OS limit is 107 bytes; on a stale ax clone (9-digit `%N` timestamp + a 16-char random socket suffix) the path length is `75 + len(module) + len(node_ip)`, so it overflows when `len(module)+len(node_ip) ≥ 33` — surfacing as `unix_listener: path "…" too long for Unix domain socket` and `Preflight: N/M instances reachable, retrying…`. On IPv4 only `puredns-bruteforce` (18 chars) is long enough, and only on nodes whose public IP is the full 15 chars (every octet 100–255, ~1 in 7) — so it's intermittent and puredns-specific; shorter module names (nuclei/httpx/nmapx/feroxbuster/…) never overflow on IPv4. An IPv6 fleet (node IPs up to 39 chars) would break nearly everything. **This is not a MonkeyX bug** — the socket path is built from the ax `-m` module name + ax timestamp + the fleet node's IP; our `-o` output name plays no role. The failing node fails preflight deterministically (retries can't shorten a fixed-length path); ax then runs on the reachable subset (or aborts, depending on fork). **Fix:** update ax on the scan server (`cd ~/.axiom && git pull`) — current `attacksurge/ax` main shortened the socket path (`%1N` timestamp, bare `%h`, no random suffix → max ~83 chars). Fallback if pinned to an old ax: set `ControlPath ~/.ssh/cm-%C` in ax's ssh config.
- **Fleet name auto-generated**: The `-f` flag is optional. If omitted and the run includes fleet-requiring modules, a name like `monkeyx-a7f3` (random 4-char hex suffix) is generated automatically. The fleet is spun up and torn down as normal. If ALL modules in a run are in `_NO_FLEET_MODULES` (`workflows.py` — the local-only set: normalize, analyze, focus, ai_analyze, ai_analyze_gowitness, ai_validate, jsonl_to_csv, nmap_converter, dns_resolve, dnsx_resolve, subfinder, nessus_import, all `bbot_*`, dns_security, html_report, summary, shodan_enrich, ssh_audit_scan, snmp_sweep, smtp_security), no fleet is created at all and the fleet kwarg is set to `"local"` as a placeholder.
- **Axiom auth is optional**: `iauth()` resolves the account name in order (highest wins) `--ax-account` flag → `AXIOM_ACCOUNT` env var → `monkeyx.config` `fleet.account` (via `core.config.get_axiom_account()`). If none is set, auth is skipped (assumes user already authenticated). Auth failures are logged with exit code and stderr details.
- **Step failures don't abort the run**: If a module raises an exception or returns a failed result, the engine logs the failure, appends a failed result, and continues to the next step. Only `KeyboardInterrupt` (pause/cancel) halts execution. URL-dependent modules (ax_nuclei, ax_gowitness, ax_feroxbuster, ax_ffuf) return graceful failures when their URL file is missing rather than raising.
- **ax_nmap_tcp parses results**: `ax_nmap_tcp` calls `nmap_to_tcphosts()` after merge to produce `{prefix}-tcpscan-alive-hosts.txt` and `{prefix}-tcpscan-weburls.txt`. This ensures IPs and URLs are logged to the ledger from the first scan step.
- **weburls.txt includes both IP and hostname URLs**: `nmap_to_tcphosts()` / `nmap_to_udphosts()` extract hostnames from each `<host><hostnames><hostname>` element via `extract_hostnames()` and emit URLs for the IP **and** every hostname. So a host with reverse DNS `web.example.com` and IP `10.0.0.1` on port 443 produces both `https://10.0.0.1` and `https://web.example.com` in `{prefix}-{module_id}-weburls.txt`. This matters for vhost-routed apps and TLS SNI — hitting the IP alone often returns a default vhost or cert mismatch instead of the real application. Downstream tools (ax_nuclei, ax_gowitness, ax_ffuf, ax_feroxbuster) then scan both forms.
- **Hostname-aware URL synthesis**: Two synthesis paths give web modules the right URLs (IP-form and hostname-form, with correct schemes per port). (1) **Nmap parse-time cross-reference**: after any module declaring `PRODUCES = {"nmap_xml": "..."}`, the orchestrator reads its weburls.txt and, for every IP-form URL, emits hostname URLs (with the same scheme+port) for hostnames the ledger maps to that IP via `dns_resolve` parents. Schemes inherit from nmap's classification (`tunnel="ssl"` → https, otherwise http) so no spurious URLs are generated. (2) **User URL normalization** (`normalize_user_url()` in `target_ledger.py`): bare hostnames in `-url` are expanded to both `http://host` + `https://host`; URLs with explicit schemes pass through unchanged. Synthesized URLs are logged with `source: "url_synthesis_nmap"` or `source: "user_input"` for audit. Multi-hostname IPs are handled via `_parents_by_target` (a single IP resolved from multiple hostnames generates URLs for each).
- **Auto-injection of `ax_nmap_tcp`**: When a web-consuming module (declaring `CONSUMES_URLS = True`) appears in the pipeline without a URL source ahead of it, `monkeyx.py` injects `ax_nmap_tcp` (and `dns_resolve` first if domains are present and dns_resolve hasn't run yet). `ax_nmap_tcp` feeds its results through the same nmap-XML cross-reference (Trigger 1), producing hostname URLs with **only** the schemes/ports that are actually open — no double-emit of http+https for hostnames whose IPs would never serve them. Skipped automatically when a module in the skip-set `{ax_nmap_tcp, ax_nmap_udp}` is already in the pipeline (those produce nmap XML covering the same purpose). Disable with `--no-auto-discovery`. In `--continue` mode, auto-injection is also skipped if the existing ledger already has URL entries (reusing prior scan data). New web modules opt in with `CONSUMES_URLS = True`; new nmap-producing modules opt in with `PRODUCES = {"nmap_xml": "..."}`.
